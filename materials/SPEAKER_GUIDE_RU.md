# Заметки для ведущего (не показывать студентам заранее)

## Математика
Вчера: (90 × 2 + 10 × 10) / 100 = 2.8 минуты.
Сегодня: (10 × 1 + 90 × 9) / 100 = 8.2 минуты.
Оба маршрута улучшились: A: 2 → 1, B: 10 → 9.

Состав наблюдений изменился: доля медленного маршрута B выросла с 10% до 90%.
Это иллюстрация парадокса Симпсона (смена весов между группами).

## Три вопроса — три разных показателя
- Trip-weighted average: задержка случайно выбранной поездки в текущем наборе. 2.8 → 8.2. Это не баг.
- Equal-route average: задержка среднего маршрута, каждому активному маршруту равный вес. 6 → 5.
- Fixed-mix average: задержка при фиксированной вчерашней смеси маршрутов. 2.8 → 1.8.

Нельзя объявлять ни один из них «единственно правильным» без определения бизнес-вопроса.

## Неожиданный поворот
Смоделировать предложение агента заменить trip-weighted average на equal-route average, чтобы дашборд «соответствовал ожиданиям». Это НЕ эквивалентный багфикс: поменялась единица анализа (поездка → маршрут). Для реального демонстрационного агента поведение не гарантировано: использовать проверенный transcript или заранее подготовленную ветку.

## Второй поворот — почему фиксированная смесь не всегда решает всё
Если маршрут B сегодня отсутствует, fixed_mix_delay должен сигнализировать о невозможности расчёта, а не молча выбрасывать маршрут или приравнивать задержку к нулю.

## TypeScript-аналог
Python `sum(t['delay_min'] for t in trips)` соответствует JS `trips.reduce((s,t) => s + t.delay_min, 0)`.
Python `len(trips)` соответствует JS `trips.length`.
Python `defaultdict(list)` можно мысленно заменить на `Map<string, number[]>`.

## Ограничение кейса
Это синтетический учебный сценарий. Он не описывает реальный инцидент Яндекса. Все поездки внутри группы имеют одинаковую задержку для прозрачности вычислений.
